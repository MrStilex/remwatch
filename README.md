# remwatch

`remwatch` — панель для мониторинга нод, просмотра логов в Loki и управления подключенными источниками логов.

> Важно: проект находится на ранней стадии разработки (WIP). Интерфейс, схема агентов и API еще меняются. Проект ориентирован на AI/automation сценарии и пока не выглядит как стабильный production-ready продукт.

## Что это сейчас

Проект состоит из двух частей:
- `frontend` — React/Vite интерфейс панели.
- `backend` — Fastify API, которое работает с Loki, реестром нод и реестром подключенных сервисов.

Основной сценарий использования сейчас такой:
- добавить ноду;
- подключить агент;
- смотреть метрики и ошибки ноды;
- подключать отдельные сервисы и боты;
- искать их логи;
- удалять лог-источники из интерфейса.

## Страницы

### Dashboard
Маршрут: `/`

Что есть на странице:
- настраиваемый набор панелей, который хранится в `localStorage` браузера;
- карточка метрик панели;
- карточка логов панели;
- карточка логов страницы подписок.

Что можно делать:
- добавлять панели через меню `+ Добавить`;
- удалять панели;
- смотреть общую сводку по пользователям, нодам и трафику;
- смотреть логи панели и логи страницы подписок в одном экране.

Текущее ограничение:
- состав панелей пока сохраняется локально в браузере, а не в общей серверной конфигурации.

### Nodes
Маршрут: `/nodes`

Что показывает:
- список подключенных нод;
- статус ноды (`Online / Offline`);
- страну и IP;
- CPU, RAM, Disk;
- сетевой входящий и исходящий трафик;
- количество ошибок за последний час;
- время последнего лога.

Что можно делать:
- сортировать таблицу по основным колонкам;
- скрывать и показывать колонки;
- открывать детальную страницу конкретной ноды;
- добавлять новую ноду;
- удалять ноду.

Как сейчас работает добавление ноды:
- UI создает запись ноды в backend;
- backend создает отдельную service-binding запись для нодового агента;
- UI выдает команду установки нового нодового агента;
- агент ставится в `/opt/remwatch-node-agent`;
- агент отправляет логи через backend ingest с токеном, а не напрямую в Loki.

Как сейчас работает удаление ноды:
- удаляется запись ноды;
- удаляется backend binding нодового агента;
- ставится tombstone для лог-источника;
- логи ноды больше не должны оставаться в списке `Logs` сразу после удаления.

### Node Detail
Маршрут: `/nodes/:name`

Что показывает:
- статистику ошибок по выбранной ноде;
- график ошибок по времени;
- круговую диаграмму по типам ошибок;
- суммарные карточки по типам ошибок;
- последние события по конкретному типу ошибки.

Что можно делать:
- переключать период (`1ч`, `6ч`, `24ч`, `7д`);
- открывать модалку с последними ошибками конкретного типа;
- копировать последние события из модалки.

Эта страница ориентирована именно на ошибки Xray/remnanode, а не на полный системный журнал сервера.

### Logs
Маршрут: `/logs`

Это страница списка лог-источников.

Что показывает:
- `Service` — имя сервиса;
- `Node` — имя узла или сервера;
- `IP` — IP, если он известен из backend binding или из последней записи Loki;
- `Type` — тип источника (`systemd`, `file`, `node`, `heartbeat`, либо legacy поток без новой схемы);
- `Файл / Unit` — systemd unit, путь к файлу или технический контейнер или источник;
- `Last Update` — время последней найденной записи;
- `Status` — текущее состояние привязки или источника.

Что можно делать:
- загружать список источников по периоду;
- удалять лог-источник из интерфейса.

Как сейчас работает удаление на этой странице:
- для managed-источников удаляется и история, и backend binding;
- для legacy-источников удаляется история и ставится tombstone, чтобы поток не висел в списке сразу после удаления;
- если внешний сервис продолжает реально писать новые логи, он появится снова как новый активный поток.

Важно:
- эта страница сейчас показывает и managed-источники, и legacy Loki-потоки, если они все еще живы;
- если какой-то сервис пишет в Loki напрямую, token-ingest его не ограничивает.

### Website/Bot Journal
Маршрут: `/journal`

Это страница просмотра содержимого логов.

Что можно делать:
- искать по тексту сообщений;
- фильтровать по `Node Name`;
- фильтровать по `Service Name`;
- фильтровать по `Level`;
- выбирать предустановленный период;
- запрашивать весь период или собственный интервал;
- ограничивать размер выдачи.

Что показывает:
- список строк логов в виде таблицы `Message`.

Отдельно на этой странице есть кнопка `Управление`, которая открывает менеджер сервисов.

### Управление сервисами
Открывается из страницы `Website/Bot Journal`.

Что делает:
- показывает backend-реестр подключенных сервисов;
- показывает источник (`systemd unit` или `log file path`);
- показывает статус привязки;
- показывает `Last Seen`;
- позволяет добавить сервис;
- позволяет удалить сервис.

Как сейчас работает добавление сервиса:
- backend создает service binding;
- backend выдает токен один раз;
- UI строит install-команду;
- агент пишет в `/api/logs/ingest`.

Поддерживаемые режимы подключения:
- `systemd unit`;
- `log file path`.

### Login
Маршрут: `/login`

Что делает:
- вход в панель по паролю;
- установка JWT cookie;
- backend проверяет и ограничивает количество неудачных попыток входа по IP.

### Change Password
Маршрут: `/change-password`

Что делает:
- позволяет сменить пароль администратора;
- после смены backend перевыпускает токен авторизации.

## Как устроены агенты сейчас

### Нодовый агент
Используется для нод со страницы `Nodes`.

Что поднимает:
- `remwatch-vector`;
- `remwatch-node-exporter` (если на `:9100` нет уже работающего exporter).

Что читает:
- `/var/log/remnanode-supervisor/xray.out.log`.

Куда отправляет:
- в backend endpoint `/api/logs/ingest`.

Где ставится:
- `/opt/remwatch-node-agent`.

Как удаляется:
- через `node-agent-uninstall.sh`.

### Сервисный агент
Используется для сервисов со страницы `Website/Bot Journal`.

Поддерживает:
- `systemd unit`;
- `log file path`.

Куда отправляет:
- в backend endpoint `/api/logs/ingest`.

Текущий принцип:
- backend хранит токен в виде hash;
- backend сам проставляет авторитетные labels перед записью в Loki.

## Что уже переведено на новую схему

Сейчас новая token-based схема уже используется для:
- managed сервисов;
- нового нодового агента.

Старая схема прямой записи в Loki все еще может существовать для legacy источников, которые были подключены раньше вручную или отдельными старыми агентами.
